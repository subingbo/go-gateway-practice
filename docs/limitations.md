# 已知限制与练习方向

[返回 README](../README.md)

这个项目的目标是练习 Go 网关的常见组成部分，不是生产级实现。以下是当前明确的边界。

## 认证

- 只有一个内存用户，用户 ID 固定为 `dev-user-001`，没有注册与多用户
- 没有刷新令牌、令牌吊销、登出黑名单
- Token 只存在浏览器 `sessionStorage`，关闭标签页即丢失
- 密码来自环境变量，修改后需要重启网关

## 路由与上游

- 上游地址、`/api` 前缀和 2 秒超时都硬编码在 `gateway/routes.go`
- 没有配置文件、服务发现、负载均衡、健康探测
- `backend/` 是早期练习服务，与 `backend-user/` 都监听 9090，不能同时启动
- 只支持 HTTP 上游，没有 TLS、重试、熔断和连接池调优

## 指标

- 指标保存在进程内存，重启即清零
- 延迟窗口为最近 200 次，P95 只代表这个窗口
- `/health`、`/api/routes`、`/api/stats` 以及看板静态资源不计入统计
- 只有计数与延迟，没有 QPS 时间序列、错误率趋势和按状态码的明细
- 日志是 `log.Printf` 文本，没有结构化日志、请求 ID 和链路追踪

## 生命周期与安全

- 没有 `http.Server.Shutdown` 优雅退出
- 没有限流、请求体大小限制（登录接口除外）、CORS 配置和 HTTPS
- `data/jwt.secret` 由运行时生成，路径相对工作目录；当前未被 `.gitignore` 忽略，提交前需要确认
- 网关自身接口没有区分管理员与普通用户

## 前端

- 请求历史不持久化，刷新页面即丢失
- 指标来自轮询，不是 WebSocket 或 SSE 推送
- 没有展示网关的服务端日志，超时取消只能通过订单服务终端观察
- 没有端到端测试，验证以手动操作和 curl 为主

## 可以继续练习的方向

1. 把上游、超时、认证要求抽成 YAML 配置，启动时加载
2. 为 `http.Server` 增加 `Shutdown`，处理 SIGINT / SIGTERM
3. 增加 refresh token、令牌吊销和基于角色的授权
4. 增加令牌桶限流、请求体限制和上游重试
5. 用 Prometheus 指标替换或补充当前的内存统计
6. 增加请求 ID、结构化日志和 OpenTelemetry 链路
7. 为上游增加主动健康检查与负载均衡
8. 把看板的历史记录持久化，并通过 SSE 推送服务端日志
