# 在 reference/ 新增完整版：边缘网关 + 类 Istio 服务网格

## Context

你现在的练习版已经跑通反向代理、JWT 登录、超时、内存指标和 Vue 看板，但继续往下加能力时每一步都要自己摸索，速度慢。目标是在同一仓库新增一个**独立目录 `reference/`**，做一个可一键运行、可并排对照的完整版：

- **边缘网关（南北向）**：配置化路由、JWT + refresh/吊销 + RBAC、令牌桶限流、重试、主动健康检查、负载均衡、Prometheus 指标、SSE 日志、优雅退出。
- **集群内网关层（东西向，类 Istio）**：控制面（服务注册/健康检查、VirtualService/DestinationRule 下发、CA 签发证书）+ 每个服务实例旁的 sidecar（mTLS、子集权重金丝雀、故障注入、熔断、重试）。
- 正好覆盖你在 `docs/limitations.md` 里列的 8 个练习方向。

不改动现有 `gateway/`、`backend-*/`、`docs/`、根 `go.mod`；`reference/` 是独立 Go module，根目录 `go build ./...` 不会包含它。

## 总体架构

```text
                     浏览器 / curl
                          │
                 ┌────────▼─────────┐
                 │ Edge Gateway     │  :8080
                 │ JWT/RBAC/限流     │
                 │ 重试/超时/指标    │
                 │ 看板/SSE 日志     │
                 └────────┬─────────┘
                          │ mesh client（服务发现 + mTLS + LB + 熔断）
                          ▼
     ┌──────────────────────────────────────────────┐
     │ Control Plane :18000                         │
     │ registry + 主动健康检查                       │
     │ VirtualService / DestinationRule              │
     │ CA（SPIFFE 证书签发）+ SSE watch + 面板        │
     └───────▲──────────────────────────▲───────────┘
             │ SSE 配置/实例推送          │ SSE
     ┌───────┴────────┐        ┌────────┴─────────┐
     │ user-service v1│        │ order-service    │
     │ app   :9101    │        │ app   :9103      │
     │ sidecar        │        │ sidecar          │
     │ 19101 / 15001  │        │ 19103 / 15003    │
     └───────▲────────┘        └────────┬─────────┘
             │ mTLS                     │ mesh SDK（HTTP forward proxy）
     ┌───────┴────────┐                  │
     │ user-service v2│◀─────────────────┘
     │ app   :9102    │
     │ sidecar        │
     │ 19102 / 15002  │
     └────────────────┘
```

两条链路：

- **南北**：客户端 → Edge（认证/限流/重试/超时）→ mesh client（发现 + mTLS + LB）→ 目标 sidecar inbound → 应用。
- **东西**：order-service 用 mesh SDK 把请求发给本机 sidecar outbound（HTTP 代理）→ 按 VirtualService 选子集/实例 → mTLS → user-service sidecar inbound → 应用。

## 关键设计

### 1. 边缘网关

- **配置驱动**：`configs/gateway.yaml` 定义 server、auth、rate_limit、routes；支持按 mtime 轮询热重载，解析失败保留旧配置并记录错误。
- **路由**：host + 最长 path 前缀 + method + header 精确匹配；`strip_prefix` 重写；未匹配返回 JSON 404。
- **上游**：`upstream.service` 走 mesh 服务发现，或 `upstream.instances` 静态地址；两种都复用 `internal/upstream` 的 LB、主动健康检查、离群摘除、重试。
- **认证**：`POST /auth/login` 用 bcrypt 校验，签发 5 分钟 access JWT（含 `user_id`、`roles`、`jti`）和 30 分钟 opaque refresh；`/auth/refresh` 轮换 refresh（旧的立即失效），`/auth/logout` 吊销 refresh 并把 access `jti` 放入内存 denylist 直到过期。路由级 `roles` 做 RBAC。
- **限流**：手写令牌桶，按「路由 + 用户/IP」分桶，返回 429 + `Retry-After`；路由可覆盖默认 rps/burst。
- **代理**：手动执行请求（便于重试/超时/故障处理），复制响应流；超时 504、连接失败 502；请求体缓冲上限 8 MiB，仅无 body 或幂等请求重试。
- **中间件顺序**：recovery → request ID → access log（slog JSON）→ metrics → CORS → route match → auth → rate limit → proxy。OPTIONS 预检直接 204。
- **管理接口**：`/health`、`/ready`、`/metrics`、`/api/whoami`、`/api/routes`、`/api/stats`、`/api/logs/stream`（SSE，`?access_token=` 鉴权）、`/api/mesh/status`、`/api/mesh/config`（服务端代理控制面，避免跨域）。
- **优雅退出**：`signal.NotifyContext` + `Server.Shutdown(10s)`，停止健康检查、配置轮询和 SSE 客户端。

### 2. 控制面（Istiod-lite）

- **注册中心**：`POST /v1/instances/register` / `heartbeat` / `DELETE`；实例含 service、address（sidecar inbound）、labels、health URL；TTL 45s，janitor 清理；控制面对每个实例做主动健康检查（2s 间隔、连续 3 次失败标记 UNHEALTHY、2 次成功恢复）。
- **配置模型**：YAML 多文档加载 `VirtualService` / `DestinationRule`，支持：
  - `match`：path_prefix、headers、method；
  - `route`：destination subset + weight；
  - `timeout`、`retries`（attempts / per_try_timeout / retry_on）；
  - `fault`：delay / abort + percentage；
  - `DestinationRule`：subsets（labels）、LB（round_robin/random/least_request）、connection_pool、outlier_detection、peer_authentication（STRICT/PERMISSIVE）。
  - 配置变更自动 bump version；非法配置拒绝生效。
- **分发协议**：`GET /v1/watch?version=N` SSE 推送完整 snapshot（服务实例 + VS + DR + 根证书），15s 心跳；客户端断线重连并带上次 version。
- **CA**：首次启动生成 ECDSA P-256 根 CA 持久化到 `data/ca/`；`POST /v1/certs/issue` 签发短 TTL 叶子证书，URI SAN 为 `spiffe://cluster.local/ns/default/sa/<service>`；叶子证书 10 分钟有效，sidecar 在 2/3 TTL 时轮换。
- **状态接口**：`/v1/registry`、`/v1/config`、`/v1/ca`、`/v1/status`、`/metrics`、`/`（控制面面板，展示服务/实例健康、配置版本、sidecar 版本与证书到期、CA 信息）。

### 3. Sidecar（Envoy-lite）

- **启动**：拉取 snapshot + 订阅 SSE；向控制面申请自身 SPIFFE 证书并启动轮换；注册实例（address=inbound 地址）并每 10s 心跳；退出时 deregister。
- **Inbound**：TLS 监听（`tls.RequestClientCert`），手动校验证书链与 URI SAN；按 DestinationRule 的 `peer_authentication` 决定 STRICT 是否拒绝无客户端证书的请求；把验证后的身份写入 `X-Mesh-Source`（覆盖客户端伪造值）和 `X-Forwarded-Client-Cert`；用 `httputil.ReverseProxy` 转发到本机 app，传播 `X-Request-ID`。
- **Outbound**：HTTP forward proxy 监听（SDK 用 `http.Transport.Proxy` 指向它）。按 URL/Host 取目标服务，匹配 VirtualService 规则 → 故障注入 → 选 subset/权重 → 从 snapshot 过滤 HEALTHY 实例 → LB → mTLS 请求；重试时重新选实例；连接池上限与 pending 上限来自 DestinationRule；离群摘除按「连续 5xx 次数 + 摘除时长」实现，全部摘除时返回 503。
- **观测**：`/metrics`（请求数、延迟直方图、重试、摘除、配置版本、证书剩余秒数）、`/debug/config`（当前 snapshot）、`/healthz`、`/ready`；access log 记录 source identity、destination、subset、实例、attempts、status、duration。
- **SDK**：`mesh/sdk` 只是把 `http.Client.Transport.Proxy` 指向 sidecar outbound，并补 `X-Request-ID`，服务代码写 `http://user-service/users/1` 即可。

### 4. 配置示例

`configs/gateway.yaml`（节选）：

```yaml
server: { addr: ":8080", read_header_timeout: 5s, shutdown_timeout: 10s }
auth:
  issuer: go-gateway-reference
  audience: go-gateway
  access_ttl: 5m
  refresh_ttl: 30m
  secret_file: data/jwt.secret
  users:
    - { username: admin,  user_id: admin-001,  roles: [admin],  password_env: GATEWAY_ADMIN_PASSWORD }
    - { username: viewer, user_id: viewer-001, roles: [viewer], password_env: GATEWAY_VIEWER_PASSWORD }
rate_limit:
  default: { rps: 50, burst: 100 }
  routes: { "/api/orders/": { rps: 10, burst: 20 } }
routes:
  - name: users
    match: { path_prefix: /api/users/, methods: [GET], strip_prefix: /api }
    upstream:
      service: user-service
      timeout: 2s
      retries: { attempts: 2, per_try_timeout: 500ms, on: [5xx, reset, connect] }
      load_balancer: round_robin
      outlier_detection: { consecutive_5xx: 5, ejection_time: 10s }
    auth: { required: true, roles: [admin, viewer] }
  - name: orders
    match: { path_prefix: /api/orders/, strip_prefix: /api }
    upstream: { service: order-service, timeout: 2s, retries: { attempts: 2, on: [5xx] } }
    auth: { required: true }
  - name: admin
    match: { path_prefix: /api/admin/, strip_prefix: /api }
    upstream: { service: order-service }
    auth: { required: true, roles: [admin] }
```

`configs/mesh/virtualservices.yaml`（节选，规则按顺序匹配）：

```yaml
apiVersion: mesh/v1
kind: VirtualService
metadata: { name: user-service }
spec:
  hosts: [user-service]
  http:
    - name: canary-header
      match: [{ headers: { x-canary: "true" } }]
      route: [{ destination: { subset: v2 }, weight: 100 }]
    - name: faulty
      match: [{ path_prefix: /users/faulty }]
      fault: { abort: { percentage: 100, http_status: 500 } }
      retries: { attempts: 2, per_try_timeout: 300ms, retry_on: [5xx] }
      route: [{ destination: { subset: v1 }, weight: 100 }]
    - name: default
      route:
        - { destination: { subset: v1 }, weight: 90 }
        - { destination: { subset: v2 }, weight: 10 }
      timeout: 2s
      retries: { attempts: 2, per_try_timeout: 500ms, retry_on: [5xx, reset, connect] }
```

`configs/mesh/destinationrules.yaml`（节选）：

```yaml
apiVersion: mesh/v1
kind: DestinationRule
metadata: { name: user-service }
spec:
  host: user-service
  subsets:
    - { name: v1, labels: { version: v1 } }
    - { name: v2, labels: { version: v2 } }
  traffic_policy:
    load_balancer: least_request
    connection_pool: { max_connections: 100, max_pending_requests: 50 }
    outlier_detection: { consecutive_5xx: 5, ejection_time: 10s }
    peer_authentication: PERMISSIVE
```

### 5. 可观测性

- **Prometheus 文本**（手写 registry，不引入 client_golang）：
  - Edge：`gateway_http_requests_total{route,method,code}`、`gateway_http_request_duration_seconds_bucket{route,le}`、`gateway_http_in_flight`、`gateway_upstream_healthy{cluster,instance}`、`gateway_upstream_retries_total{cluster}`、`gateway_ratelimit_rejected_total{route}`、`gateway_auth_failures_total{reason}`。
  - Sidecar：`mesh_requests_total{direction,source,destination,code}`、`mesh_request_duration_seconds_bucket{...}`、`mesh_retries_total{destination}`、`mesh_outlier_ejections_total{destination,endpoint}`、`mesh_config_version`、`mesh_cert_expiry_seconds`。
  - Control Plane：`mesh_registry_instances{service,status}`、`mesh_watch_clients`、`mesh_config_version`、`mesh_ca_certs_issued_total`。
- **看板**：
  - Edge `/`：登录、请求构造器（预设 users/orders/slow/faulty/admin）、响应面板、RPS/P95/错误率卡片、路由与上游健康表、Mesh 面板（注册中心/配置版本/sidecar 证书）、SSE 实时日志、最近请求表。
  - Control Plane `/`：服务/实例健康、VS/DR 摘要、sidecar 舰队（配置版本/证书到期）、CA 信息。
  - 均为 `go:embed` 单文件原生 JS，无构建步骤。
- **日志**：`log/slog` JSON 输出，同时 tee 到环形缓冲（500 行）+ SSE 订阅；access log 带 `request_id`。

### 6. 生命周期

- 所有进程统一 `signal.NotifyContext(os.Interrupt, syscall.SIGTERM)` + `Server.Shutdown`；sidecar 退出前 deregister；控制面停止健康检查/janitor/SSE。
- `cmd/devstack` 负责构建一次二进制到 `.run/bin`、按依赖顺序启动、探测就绪、转发带前缀日志；Windows 下无法向子进程发 Ctrl+C，退化为 Kill，单独运行各二进制时仍可验证优雅退出。

## 验证方式

```bash
cd /d/code/go-gateway-practice/reference
go build ./... && go vet ./... && go test ./...
go run ./cmd/devstack          # 另开终端做下面的检查
```

关键验收场景：

1. `POST /auth/login`（admin/admin123）成功；无 token 访问 `/api/whoami` 返回 401；viewer 访问 `/api/admin/ping` 返回 403。
2. `/api/users/1` 连续 20 次，响应中 v1/v2 约为 90/10；带 `x-canary: true` 全部 v2。
3. `/api/orders/1` 返回订单 + 通过 mesh 获取的用户信息；`/api/orders/slow` 约 2 秒后 504。
4. `/api/users/faulty` 触发故障注入 + 2 次重试，最终 500；`mesh_retries_total` 增加。
5. 令牌桶：对 `/api/orders/` 突发请求出现 429。
6. refresh 轮换：旧 refresh 再用返回 401；logout 后 access token 立即失效。
7. `curl -k https://127.0.0.1:19101/users/1` 在 PERMISSIVE 下可访问；把 DR 改成 STRICT 并等待热重载后返回 403，而 mesh 内调用仍 200。
8. 杀掉 user v1 sidecar：控制面 registry 移除实例，流量转到 v2；`--chaos` 下观察离群摘除与重试恢复。
9. `/metrics`（edge、sidecar、control plane）包含上述指标；看板登录、请求、Mesh 面板、实时日志正常。
10. `scripts/e2e.sh` 自动跑完核心场景并退出，无残留进程。

## 风险与边界

- **YAML 依赖**：默认 `gopkg.in/yaml.v3`；若当前环境无法拉取，实施时先验证 `go mod tidy`，失败则退化为 JSON 配置（接口不变，只换解码器）。
- **Windows 进程管理**：devstack 在 Windows 上无法优雅中断子进程，会 Kill；优雅退出逻辑通过单独运行二进制 + Ctrl+C 验证。
- **PERMISSIVE 语义简化**：本实现中 inbound 始终是 TLS，PERMISSIVE = 允许无客户端证书；不实现 Istio 的明文/mTLS 同端口嗅探。
- **非生产**：控制面 API 无鉴权、CA 私钥与证书通过 localhost 明文接口分发、demo 密码来自环境变量；文档中会明确标注。
- **不做**：Kubernetes/Docker/Envoy/gRPC xDS、完整 Istio CRD、WebSocket、HTTP/2、边缘 TLS。
- **范围控制**：看板最后实现，若时间紧可先保留 JSON 接口；后端与 mesh 功能不受影响。
